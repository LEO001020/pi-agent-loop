# Internationalization (i18n)

**Rule:** User-visible UI strings must not be hard-coded. Use `t(locale, key)` / `createT(locale)`.

**Product default locale is English (`en`).** Optional locales: `zh` (Simplified Chinese), `zh-TW` (Traditional Chinese). All three catalogs must share the same keys (`messages.test.ts` enforces this).

## Source locations

| Path | Role |
|------|------|
| `src/i18n/messages.ts` | Catalog: **`en` is the key authority**; `zh` must cover every key |
| `src/i18n/zh-tw.ts` | Traditional Chinese (Taiwan) catalog |
| `src/i18n/index.ts` | `t` / `createT` / `resolveLocale` / types |
| Components | Reference keys only — never hard-code `"Settings"` |
| `src-tauri/src/tray_i18n.rs` | Native tray strings (keep in sync with `tray.*` keys; reads `settings.locale`) |

## Adding or changing copy

1. Add the key to the **`en` object** in `messages.ts` first (dot keys: `area.action`).
2. **Same PR:** fill `zh` and `zh-tw.ts` with complete translations.
3. In components: `const tr = useMemo(() => createT(locale), [locale]);` then `tr("sidebar.settings")`.
4. Variables: template `{name}`, call `tr("project.trustFirst", { name: proj.name })`.
5. Do **not** spread `locale === "zh" ? "…" : "…"`; replace leftovers with keys.
6. Product / model names (`Pi 4.5`, `Agent`) may stay English; descriptive UI must be translated.
7. Language switch writes `settings.locale` and updates UI immediately.
8. Prefer `createT(locale)` over partial label maps (missing keys show raw `settings.foo`).

## Defaults

| Layer | Default |
|-------|---------|
| `AppSettings.locale` | `"en"` |
| `resolveLocale(undefined)` | `"en"` |
| Tray unknown locale | English |
| Settings language dropdown | English listed first |

## Translation quality

- **English:** primary product language for open source; clear, concise desktop tone.
- **Chinese:** complete sentences, consistent product tone; optional for users who switch locale.
